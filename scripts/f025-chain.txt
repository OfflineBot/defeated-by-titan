# a leg only if a rope is on it, and every leg here says so.
#
# Each leg holds its arm 0.12 s LONGER than the wait before the mark, so the rope is still on
# at the mark; the 0.15 s afterwards lets the hold expire before the next arm fires. The arms
# alternate right/left/right/left/right, so `rope == 1` at a mark is the arm fired for THAT
# leg and not the one before it.
#

# =====================================================================================
# ACT 1 — FIVE SWAPS AT FULL SNAP. **The acceptance.**
# =====================================================================================
# Measured 2026-08-19 [offlinebot], dropped from the beam line at (0, 58, 257.5):
#
#   leg   anchored   speed        height     what it is
#   1     yes        16.890 m/s   50.862 m   the first arc, released early and high
#   2     yes        27.467       39.010
#   3     yes        34.828       27.520
#   4     yes        39.370       19.084
#   5     yes        45.232        6.670     7.5x running speed, on zero gas
#
# Strictly monotone over five swaps, and the whole 44 m of descent is spent buying it:
# v²/2 + g·h is 143 + 1017 at leg 1 and 1023 + 133 at leg 5 — the same 1160 J/kg. That is what
# "accelerate a trajectory" means here, and it is why the rope has to be on: a chain that
# anchors nothing descends exactly as fast and arrives on the pavement.
settings assist_catch 100
settings assist_strength 100
warp 0 58 257.5
look 0 0
wait 0.1

# 🔴 RED ON PURPOSE SINCE 2026-08-29 — 8 of 36, AND NOT ONE OF THEM IS A DEFECT. Re-measured
# after `gravity_m_s2` -20 -> -32. This file was staged as a DESCENT: each leg's `look` angle is

# =====================================================================================
# ACT 3 — NEVER A POINT BEHIND YOU. The cheap half, and it is one number twice.
# =====================================================================================
# On the boulevard at (150, 2, -60). The wall gallery — a 700 m anchorable ledge at y = 59
# that projects 14 m out over the boulevard — is 27.6 m away in −Z and 57 m up, so it sits
# at 64° of elevation from the pavement. Behind him (+Z) stands the town: roofs at 11 m.
#
# Two shots from the same tile, both at 100 % / 100 %, both at pitch 64. The only difference
# is which way he faces. Reeled in for 3 s afterwards, so where he ends up IS the measurement
# — no assertion here asks the aiming code what it chose:
#
#   yaw 0   (gallery ahead)    hooks, reels to **60.746 m**   — the ledge
#   yaw 180 (gallery behind)   hooks, reels to  **5.723 m**   — a roof in front of his face
#
# The 60 m ledge is eight metres behind his back in the second shot and the assist does not
# take it. That is the acceptance's second half, measured: the catch cone is 20° wide at
# 100 % (`shared::settings::ASSIST_CATCH_MAX_DEG`), so a point behind the crosshair is not a
# candidate at all — `tests/vector_hooks.rs::f024_never_a_point_behind_the_player` proves the
# geometry, and this proves the consequence in the running game.
#
# ⚠️ Ctrl is held here, so gas IS spent from this point on. That is why this act is last.
settings assist_catch 100
settings assist_strength 100
wait 3.2
warp 150 2 -60
look 0 64
wait 0.3
mark f025-ahead-fire
assert height < 2.0
hook right 4.0
wait 0.7
mark f025-ahead-hooked
assert rope == 1
key Ctrl 3.0
wait 3.3
mark f025-ahead-reeled
assert height > 40.0          # 60.746 — the gallery, the usable point that lay ahead
wait 1.2

warp 150 2 -60
look 180 64
wait 0.3
mark f025-behind-fire
assert height < 2.0
hook left 4.0
wait 0.7
mark f025-behind-hooked
assert rope == 1              # it finds something — it just does not find THAT something
key Ctrl 3.0
wait 3.3
mark f025-behind-reeled
assert height < 20.0          # ★ 5.723. A roof in front of him, not the 60 m ledge behind.
wait 1.0
