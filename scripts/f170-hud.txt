# f170-hud — the HUD over a populated frame, with the F3 overlay beside it.
#
#   cargo run -q -- --offscreen --script scripts/f170-hud.txt --ticks 320 \
#       --screenshot docs/images/f170-hud.png
#
# and, as a separate run, the one that returns a usable exit code (see `scripts/f-001-hooks.txt`
# for why the two cannot be one command):
#
#   cargo run -q -- --headless --script scripts/f170-hud.txt --ticks 900
#
# ⚠️ The verdict tick moved with the boost: the script now ends at **613** (measured), and the
# 600 that used to stand here truncated the run — "instruction 16 of 16 is still running", which
# is an ERROR since FIND-032 and says nothing about the HUD.
#
# ## Why the tank is emptied before the picture is taken
#
# **A full bar is the one bar that proves nothing.** `F-170`'s named failure is "the bar that
# is a picture of a bar" (`docs/PLAN-GAME.md` §8) — an element that is present, looks right,
# and is wired to a constant. At 100 % gas a hard-coded bar and a working one are the same
# pixels. So gas goes out of the tank first: `game.ron` gives `vector.gas_boost_per_s = 18`,
# the two asserts below hold the result to 14946 ± 0.35 (the bracket is one tick of boost
# wide, for the reason `scripts/f-018-gas.txt` sets out).
#
# 🔴 **THE RULER CLAIM IS SUSPENDED AS OF 2026-08-20 — READ THE BLOCK TWO PARAGRAPHS DOWN.**
# The sentence that used to close this paragraph was "and the gas bar in the image has to be
# **82 % long, not full**. That is a number you can hold a ruler against." It is no longer
# true and no arrangement of `key Shift` in this file can make it true again.
#
# ⚠️ **THE BOOST IS THREE SECONDS AND IT USED TO BE ONE — the tank changed size under this
# file.** `vector.gas_tank` was 100 when this script was cut, so one second of boost was
# 100 − 18 = 82 and "82" was both the gas figure and the percentage. The tank became **300**
# with Q-033, so that same second left 282 — the asserts read `< 82.35` against a measured
# **281.701** and the run exited 1, and worse, a 282/300 bar is **94 % long**: a picture of an
# almost-full bar, which is the exact failure the file was written to rule out. Three seconds
# is 54 gas, 300 − 54 = 246, and 246/300 is **82 %** again.
#
# ⚠️ That moved the ticks with it: +120, so the last mark is at t=312 and the picture is shot
# at **320**, not 200.
#
# 🔴 **AND ON 2026-08-20 THE SAME THING HAPPENED A THIRD TIME, AND THIS TIME THE TRICK RAN
# OUT.** The user raised `vector.gas_tank` 300 -> 15000 („mach das 50 fache!",
# docs/QUESTIONS.md Q-046). Three seconds of boost still costs 54 gas — the asserts below are
# the old ones shifted by +14700 and their width is untouched — but `src/hud/gas_bar.rs:89`
# draws `gas.fraction() * 100`, so the bar in the PNG is now
#
#       14946 / 15000 = **99.64 % long** — i.e. FULL to any ruler ever held against it.
#
# **The fix that worked twice does not work a third time.** Lengthening the boost until the
# percentage comes back to 82 needs 2700 gas = **150 s of held boost = 9000 ticks**, and a
# headless run is wall-clock locked at 60 Hz (measured 2026-08-20: 3094 ticks take 52 s
# whether the player flies or stands still). That is 2.5 minutes for the verdict and 2.5 more
# for the picture, to photograph one bar. And it is not a tuning accident — at a 15000 tank
# **no cheap action moves this bar at all**: 99 % costs 150 gas, 82 % costs 2700, 50 % costs
# 7500. A bar that is a fraction of a tank fifty times too big is a bar that always reads full.
#
# **So the ruler claim is suspended rather than faked, and here is where each half lives now:**
#   - "the bar is driven by `Gas` and is not a picture of a bar" — F-170's named failure — is
#     held by `tests/hud.rs`, which builds its OWN `Gas::full(100.0)` and asserts the node
#     width against it. That test does not read `game.ron` and did not move today.
#   - the PIXEL half has no home until a script can set a small tank. The proposal is a
#     `settings gas <n>` verb in `src/debug/script.rs` — foreign territory to the change that
#     caused this, so it is written up in `docs/FINDINGS.md` instead of taken quietly. With it
#     this file asks for a 300 tank in one line and the 82 % bar comes straight back.
#   - **`docs/images/f170-hud.png` is stale**: it shows the 82 % bar of the 300-gas era. It is
#     NOT retaken here, because a 99.64 % bar is not evidence of anything and replacing a
#     useful old picture with a useless new one is not an improvement. Treat F-170's pixel
#     evidence as unevidenced until the override exists.
#
# The boost points straight up (`look 0 89`, `camera.pitch_limit_deg`) so that it has no
# horizontal unknown in it; the viewpoint afterwards is the one `scripts/p1-overlay.txt`
# already proved a populated frame from.
#
# ## What is in the picture, and what is honestly NOT
#
#   gas bar, bottom left, cyan      — reads `Gas`, producer `vector`               : VISIBLE
#   blade pips + sharpness, right   — reads `Blades`, producer `player::spawn`     : VISIBLE
#   crosshair, centre, four ticks   — reads `AimPoint`, producer `vector::aim`     : VISIBLE
#   health bar, bottom centre       — reads `Health`, **no producer** (job R3-A)   : HIDDEN
#   objective line, top centre      — mission state, **no producer** (job R3-B)    : HIDDEN
#
# The last two are hidden **on purpose and by test** (`tests/hud.rs`). An element that shows a
# number nobody produced is the failure this picture exists to rule out, so an empty corner is
# the honest state of the build and not a missing feature.
#
# ⚠️ The 320 ticks belong to THIS file: the last mark falls at t=312. Whoever changes a `wait`
# changes the image.

wait 1.5                 # 90 ticks: world, camera, meshes and the render pipelines come up

look 0 89                # straight up — the boost then has no horizontal component
key Shift 3.0            # three seconds of gas: 15000 - 54 = 14946. ⚠️ 14946/15000 is a
                         # 99.64 % bar, NOT the 82 % this file was built around — see the 🔴
                         # block in the header. The gas ARITHMETIC below is still exact and
                         # still goes red; only the picture stopped carrying a claim.
wait 3.0
mark f170-tank-after-three-seconds
assert gas < 14946.35      # game.ron: vector.gas_boost_per_s = 18, plus/minus one tick.
                           # 3 s x 18 = 54 out of 15000; the old bracket +14700, width kept.
assert gas > 14945.65

look 0 -26               # the viewpoint of scripts/p1-overlay.txt: a populated frame
warp 0 70 130
wait 0.3                 # the warp takes effect one tick later than it is written

key F3 0.05              # the overlay on, so the digits stand in the same PNG as the bars
wait 0.3
mark f170-hud
assert gas < 14946.35      # unchanged: coasting is free, nothing is drawn while falling
assert gas > 14945.65

wait 5                   # keep the run alive: if it ends, the process ends before the image
