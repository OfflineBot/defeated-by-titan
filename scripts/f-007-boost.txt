# f-007-boost — the gas boost, photographed from a height nothing else in this build reaches.
#
#   cargo run --features wayland,audio -- --offscreen --script scripts/f-007-boost.txt \
#       --ticks 300 --screenshot docs/images/f-007-boost.png
#
# and, as a SEPARATE run, the one that returns a usable exit code:
#
#   cargo run -q -- --headless --script scripts/f-007-boost.txt --ticks 900
#
# ⚠️ **A `--screenshot` run is not a verdict.** `debug::screenshot::exit_when_written` owns the
# ending and writes `AppExit::Success` the moment the PNG is on disk, without ever reading
# `run.failures` — so the command above exits 0 even when the asserts in this file are RED, and
# the assert summary never prints (`docs/FINDINGS.md` FIND-073). That is not hypothetical here:
# this file sat at **2 of 13 red behind an exit 0** until 2026-08-12, because `gas_tank` grew
# from 100 to 300 under it and only the headless run could say so. Its tick count is
# deliberately generous: overshooting the script's own end is free, undershooting truncates the
# run and hides the summary (FIND-032).
#
# **The height IS the measurement.** `assets/data/game.ron` says it in so many words next to
# `jump_speed_m_s`: 6.5 m/s against g = -20 give an apex of 1.056 m — "without gas you get on
# top of nothing in this city". There is no second source of upward motion in this build, so
# every meter above that one came out of the tank.
#
# Two seconds of `boost_m_s2 = 34` at 89 degrees (`camera.pitch_limit_deg`) give 33.99 m/s^2
# upwards against 20 of gravity: 13.99 m/s^2 net. Straight up, so that the picture has no
# horizontal unknown in it and every block in the frame can be projected from the one number
# the asserts measure.
#
# `look 0 -89` before the picture turns the camera only (`render::camera::rotate_camera`) —
# the boost is long over by then. Without it the image is 1280x720 pixels of dark gray
# `ClearColor`, which is a true photograph of nothing.
#
# ---------------------------------------------------------------------------------------
# ⚠️ **THE IMAGE HALF OF THIS FILE IS STALE AND THE ASSERT HALF IS NOT.** The block below
# projects the three explicitly placed cubes of the **graybox** map. `maps.ron: current` is
# `"ashgate"` since 2026-08-12 (`F-003`), so those cubes are not under the camera any more and
# every pixel figure below describes a photograph that can no longer be taken. It is kept, not
# deleted, because it is the worked example of how a picture gets held to a number — whoever
# retakes `docs/images/f-007-boost.png` re-derives the same three rows against ashgate's own
# blocks and replaces this block wholesale.
#
# **The asserts are unaffected and they are the verdict**: height, speed and gas out of a boost
# fired straight up from the spawn point do not depend on what is standing underneath.
# ---------------------------------------------------------------------------------------
# The image is a MEASUREMENT, and this is how to re-check it `[offlinebot]` — FOR THE GRAYBOX
#
# Camera at (0, 48.354 + 1.6, ~ -2.9), looking 89 degrees down, vertical FOV 60 degrees over
# 720 rows. Project the three explicitly placed blocks of `assets/data/maps.ron` and compare
# against the pixels — predicted before the run, then read out of the PNG:
#
#   block (maps.ron)                      predicted            measured in the PNG
#   brick-red 8 m  (-12, 4, -20)          (463, 118), 118 px   (462.5, 117.5), 118 px
#   sand-brown 4 m (  0, 2, -12)          (640, 247),  54 px   (639.5, 251.0),  54 px
#   stone-gray 10 m wide (10, 5.75, -28)  col 800,    160 px   col 800.5,      160 px
#
# The 8 m cube's top face is 118 px wide. From 20 m up it would be 367 px, from 100 m up
# 53 px — and from the 1.056 m a jump reaches, the camera at 2.66 m sits BELOW that roof and
# the picture cannot exist at all. Height, and nothing else, sets that number.
#
# Also read off the file: 91.4 % of the frame is ground, and there are **zero** `ClearColor`
# pixels — at 89 degrees down the horizon lies 30 degrees outside the top edge, so there is no
# sky in the frame to mistake for one. Zero cyan and zero crimson pixels: the signal colours
# stay reserved for gameplay (`docs/conventions.md`).
# ---------------------------------------------------------------------------------------

wait 1.5                 # 90 ticks: world, camera, meshes, pipelines — and the 2 m fall

mark f-007-on-the-ground
assert height < 0.05     # standing, not still falling
assert height > -0.05    # and not sunk into the ground
assert gas == 15000        # full tank, nothing spent yet — game.ron: vector.gas_tank

look 0 89                # straight up; 89 is camera.pitch_limit_deg
key Shift 2.0            # BOOST is ShiftLeft (src/net/local.rs) — held, not tapped
wait 2.0

mark f-007-button-released
assert height > 28.5     # a jump reaches 1.056 m. 28.9 m is gas, and nothing else.
assert height < 29.5
assert speed > 27.5      # 13.99 m/s^2 net over 121 ticks
assert speed < 28.5
assert gas > 14963.5     # 121 ticks at gas_boost_per_s / 60 = 0.3 -> 36.3 out of 15000
assert gas < 14964.0     # measured 14963.724 (it was 263.701 while gas_tank was 300; both
                         # bounds shifted by +14700 and the 0.5 WIDTH is untouched — this is
                         # the tightest gas bracket in scripts/ and it still clears worst-case
                         # f32 accumulation over 121 subtractions at 15000, ~0.05, by 10x)

look 0 -89               # turn the camera down onto the spot he took off from
wait 0.85                # coast on. THE COAST IS PURE GRAVITY, so this is the one number in
                         # this file that moves when `gravity_m_s2` moves:
                         #     t_apex = v0 / g = 27.732 / 32 = 0.867 s
                         # It was `wait 1.4` while g was -20 (27.9 / 20 = 1.395 s). At -32 a
                         # 1.4 s coast overshoots the apex by 0.53 s and the run reads 35.776 m
                         # FALLING at 18.250 m/s — which is what this line did for two days.
                         # 0.85 s is the nearest wait that samples the apex tick (measured:
                         # the apex sample is 53 ticks after the button, 0.867 s = 52.0 ticks,
                         # and the script's own instruction stream costs ~2 ticks).

mark f-007-apex
assert height > 40.65    # 39 times the height of a jump. DERIVED, not read off the run:
assert height < 41.35    #     h_apex = h0 + v0^2 / (2g) = 28.980 + 27.732^2 / 64 = 40.997 m
                         # and h0, v0 are not free numbers either — they are the two brackets
                         # this same script asserts eleven lines up (28.5..29.5 and 27.5..28.5).
                         # ⚠️ THE WIDTH IS THE OLD 0.70, RE-CENTRED ON THE DERIVED APEX, NOT
                         # WIDENED: 48.0..48.7 sat on 28.9 + 27.9^2/40 = 48.36 at g -20, the
                         # same +-0.35 around the same formula. Measured now: 40.942, i.e. the
                         # 0.055 m the discrete 60 Hz step loses against the continuous apex.
assert speed < 2.0       # UNCHANGED, and that is the point — the bound was already derived, so
                         # the constant moving did not move it. What is left at the apex is the
                         # horizontal drift of the 1 degree tilt plus at most two ticks of the
                         # wait landing off the apex:
                         #     drift = boost_m_s2 * cos(89 deg) * t_boost = 46 * 0.01745 * 2.017
                         #           = 1.619 m/s   (it was 34 * 0.01745 * 2.017 = 1.197 at 34,
                         #            which is the "1.2 m/s" the old comment named)
                         #     ceiling = sqrt(drift^2 + (2*g*dt)^2)
                         #             = sqrt(1.619^2 + (2*32/60)^2) = 1.939 < 2.0
                         # Measured 1.695 = sqrt(1.619^2 + 0.502^2), and 0.502 m/s is under one
                         # tick of gravity (32/60 = 0.533). The drift term grew with boost_m_s2
                         # and the tolerance term grew with gravity_m_s2, and 2.0 still holds
                         # both — so this line is evidence at BOTH tunings, not a survivor.
assert gas > 14963.5     # the climb after the button is free — nothing is drawn while coasting
assert gas < 14964.0     # ⚠️ THE UPPER BOUND IS THE CLAIM, and it was missing until 2026-08-20.
                         # "Nothing is drawn while coasting" means THE NUMBER DID NOT MOVE, and
                         # that needs both sides. This is deliberately the SAME bracket as the
                         # one at the end of the boost above, which is what makes the pair say
                         # "unchanged since then" instead of "still above some floor". A lone
                         # `>` read as a claim at a 300 tank only because it sat 0.2 under the
                         # measurement; at 15000 it was trivially true and tested nothing.

wait 5                   # keep the run alive: it must not end before the image is read back
