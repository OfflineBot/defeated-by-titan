# PINS: this file's own fall/flight (its drop and its timing are unchanged). The husk's
#       geometry is what moved: `scale.ron`'s classes DOUBLED on 2026-08-29 on the user's
#       word and `titan::rig::body_segments_m` gave the titan a neck (`docs/FINDINGS.md`
#       FIND-213), so every nape aim below is re-derived as
#         warp y  += cortex_height_m 17.80 - 8.90 = 8.90   (the drop is untouched)
#         x offset = clearance 1.55 + the air this file already chose  (was 1.60 + air)
#         z offset = set-back 1.10 + whatever this file already added  (was 0.55)
#       Nothing here was re-aimed; one input moved and the aim follows it.
#
# cargo run -- --offscreen --script scripts/q030-reach.txt --ticks 168 \
#              --screenshot docs/images/f030-solid-husk.png
#
# and, as a SEPARATE run, the one that returns a usable exit code:
#
#   cargo run -q -- --headless --script scripts/q030-reach.txt --ticks 800
#
# ⚠️ **A `--screenshot` run is not a verdict.** `debug::screenshot::exit_when_written` owns the
# ending and writes `AppExit::Success` the moment the PNG is on disk, without ever reading
# `run.failures` — so the command above exits 0 even when the asserts in this file are RED, and
# the assert summary never prints (`docs/FINDINGS.md` FIND-073). Only the `--headless` run
# reports "N asserts held" and returns an exit code worth reading. Its tick count is
# deliberately generous: overshooting the script's own end is free, undershooting truncates the
# run and hides the summary (FIND-032).
#
# Re-measured 2026-08-20 against `reach_m` 2.00: it logs `tick 154: cut titan 1 Cortex at
# 20.67 m/s (player 1)`, `MARK t=154 cortex-pass`, **2 asserts held, exit 0**. The crossing tick
# is the one this header was written with and it has been back at 154 since FIND-147; it stood at
# 157 in between (FIND-113). **Read it out of the log, never assume it.**
#
# 🔴 **The shipped `docs/images/f030-solid-husk.png` is from 2026-08-10 and is three builds
# stale.** Its F3 overlay reads `t=168 · pos -11.0 5.4 8.0 · gas 100/100 · Airborne` and
# `titan#1 Death` — a tank of 100 (it is 15000 since `F-018` on 2026-08-19), no `spd` field and no
# `Death n/60` counter. The geometry it shows is still the geometry this file flies, but it is
# **not** evidence about today's build and it wants re-shooting; it was left alone here on purpose
# (`docs/FINDINGS.md` FIND-148).
#
# ⚠️ The picture is called `f030-solid-husk.png` and not `q030-…`: `tools/norms.py` §10 knows
# f/t/b/p ids and a **question** has no letter of its own. The evidence belongs to `F-030` — it
# is the cut, against the real body instead of against the fixture in `tests/combat.rs`.
#
# `docs/QUESTIONS.md` Q-030 says this run cannot happen: `gear.ron: blades.reach_m` is 1.60 m
# and a husk's body radius plus the player's is `1.25 + 0.35 = 1.60 m`, so "there is zero
# margin". **The arithmetic leaves out two lengths that stand in the same two files.**
#
#   reach_m 2.00  +  titan.ron husk.cortex_radius_m 0.55  +  blades.thickness_m 0.20  =  2.75 m
#   against a clearance of                                    1.25 + 0.35             =  1.60 m
#                                                                            margin  = +1.15 m
#
# ⚠️ Those two gear.ron numbers were 1.60 and 0.12 until 2026-08-20 (margin +0.67 m). They grew
# because five of seven spawnable kinds could not be killed at a 0.60 m cushion and a lurker
# could not be killed at any offset at all — docs/FINDINGS.md FIND-147, scripts/f030-hitbox.txt.
#
# The blade never has to touch the titan's axis. It has to touch a **sphere** of radius 0.55 m
# that sits half a head's depth behind the neck, with a swept capsule of radius 0.20 m.
#
# This run flies the pass at **x = −1.80**, i.e. with **0.20 m of air** between the two
# capsules — a margin a player can hold, not the last centimetre of the clearance. The whole
# measured window and the same pass at `large` are in
# `tests/titan.rs::q030_a_flying_player_reaches_the_nape_of_a_solid_husk`.
#
# ## Why the player falls instead of flying
#
# The same reason as `scripts/f030-cortex.txt`: hooking, reeling and boosting cannot be aimed
# from a script accurately enough to pass a 1.10 m sphere, and gravity can. At −20 m/s² a fall
# of 11.2 m is 21 m/s and it is reproducible to the tick. What this run is evidence **of** is
# the geometry — how much air is left beside a solid body — and that does not care which way
# the player is travelling. The horizontal pass at 30 m/s is measured in the test.
#
# ## Why z = 0.55 and x = −1.80
#
# The cortex sits at `(0, 8.9, +0.55)`: `head_m / 2` **behind** the neck
# (`src/titan/rig.rs: cortex_in_head`). Standing at z = 0.55 the blade's line runs straight
# through its centre, so the only thing being measured is the lateral offset. Looking at yaw 0
# (Bevy's forward, −Z) the **right** blade lies on +X (`src/blades/cut.rs: blade_segment`), so
# the player stands on −X and the blade points inward: at `reach_m` 2.00 the segment runs from
# x = −1.80 to **x = +0.20**, i.e. it carries 0.20 m **past** the centre of a cortex sphere of
# radius 0.55. It used to stop at x = −0.20, 0.35 m inside the sphere and short of its centre.
#
# ## Why the cut lands in `Recover`
#
# Identical to `scripts/f030-cortex.txt`: the husk is 1.88 m away on the ground plane, inside
# `attack_range_m` = 6.0, so he goes `Idle → Pursue → Windup` at once and his torso leans 12°
# over the next 36 ticks — which carries the cortex almost a metre. `Windup` 36 + `Strike` 12
# put `Recover` at tick 141..165 of this run and the crossing at 154, against an upright body.
#
# 1.5 s of lead-in before anything happens: under `--offscreen` the render pipelines and the
# block meshes are still coming up in the first second.
wait 1.5
spawn titan husk 0 0 0
warp -1.75 27.4 1.10
look 0 0
key F3 0.05
# THE FALL TO THE CORTEX, AND IT IS TIMED AGAINST `gravity_m_s2` — this is the one number in the
# file that moves when the constant does. The warp is 18.5 m up, `scale.ron` puts the medium
# class's `cortex_height_m` at 8.90 m, and the blade has to be level with it when it sweeps:
#
#     t = sqrt(2 * (warp_y - cortex_y) / g) = sqrt(2 * 9.6 / 32) = 0.775 s   (it was 0.980 at -20)
#     re-timed from the old wait:  0.90 * sqrt(20 / 32) = 0.711 s
#
# ⚠️ It was `wait 0.90`, which is 0.980 s of fall at g -20 and 12.96 m of fall at -32 — the
# player arrives at 4.552 m, a metre BELOW the knee, and the run cut `LegLeft` and left the
# titan standing. That is the whole reason `assert titans == 0` below read 1.000: not a blade
# that misses, not a cortex that rejects — a slash fired after the player had already fallen
# past the head. Measured at 0.71: the player is at 9.887 m, 0.99 m over the cortex, and the log
# says `cut titan 1 Cortex at 26.67 m/s` -> `KILL`.
wait 0.71
slash right 0.40
wait 0.08
mark cortex-pass
wait 0.10
assert titans == 1
# **Only now** does the camera turn, and it steps back with it. The blade hangs at the player's
# side, perpendicular to the look direction — you cut what you fly past, not what you look at
# (`src/blades/cut.rs: blade_segment`) — so the look has to stay at yaw 0 until the blade is
# through. 17 m out and level with the nape: from 1.8 m the picture is a grey wall.
warp -11 5.5 8
look -56 -6
wait 1.10
assert titans == 0
