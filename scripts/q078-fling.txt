# q078-fling — EVERYTHING IS HOOKABLE. What still stops you from flinging yourself?
#
#   cargo run -q -- --headless --script scripts/q078-fling.txt --ticks 1300
#
# and, as a SEPARATE run, the one that returns a usable exit code:
#
#   cargo run -q -- --headless --script scripts/q078-fling.txt --ticks 1300 >/dev/null 2>&1; echo $?
#
# `docs/QUESTIONS.md` Q-078 cancelled `F-003 Getaggte Ankerflaechen`, whose stated purpose was
# *"Verhindert Physik-Exploits"*. The tag was the guard. What is left is
# `game.ron: vector.max_speed_m_s` (75, an avian `MaxLinearSpeed`), `vector.min_rope_m` (3.0),
# the rope-pull fade band, and the `DistanceJoint`'s own limits — and `F-012 Velocity-Clamp
# gegen Fling` is still Unbuilt in the ledger. **This file is the attempt to break that set.**
#
# ⚠️ **It runs on `maps.ron: current` (Ashgate) and it MUST**: the whole point is the shipped
# world. That also makes it a weak test of the *tag* change — Ashgate logs
# `2901 blocks built ... 2901 of them anchorable`, so nothing here was un-hookable yesterday
# either. The tag inversion is measured where untagged surfaces still exist, in
# `tests/vector_aiming.rs::f003_every_solid_surface_of_the_graybox_holds_a_hook_whatever_its_tag_says`.
# What THIS file measures is the thing the tag used to cover: the physics.
#
# ⚠️ Every number in a comment below was measured on 2026-08-28 against `gravity_m_s2: -32`
# and `boost_m_s2: 46`, both of which are PROVISIONAL pending the user's play test
# (`docs/NEXT.md` §3G). The asserts are therefore written around the **guards**, which are not
# provisional — `speed < 75` is `max_speed_m_s` out of the file — and the measured readings
# stand in the comments, not in the brackets, wherever a fall time decides them.

wait 1.5

# ---- ACT 1: hook the street under your own feet ----------------------------------------
#
# Q-078 named this case by itself: *„the ground. hookable. A hook into the street under your
# feet is now legal and nobody has felt it."* On Ashgate it was legal before too, so this is
# not the tag — it is the question whether a rope that points straight DOWN can throw you.
#
# Measured: anchored on body 561 at (168.19, 1.50, -50.32) — the pavement of the 4.06 m street
# of `scripts/f003-ashgate.txt` ACT 5. 0.37 s after the shot the fall reads **21.3 m/s**, which
# is about 5.8 m/s more than free fall over the same 29 ticks: the rope pull points at the
# anchor and the anchor is straight down, so it ADDS to gravity instead of opposing it.
# **That is the fling shape, and it terminates** — 3 s of `Ctrl` later he is standing on the
# street at 1.500 m with speed 0.000, because the thing he is being pulled into is the floor.
warp 168.19 12.0 -50.12
look 0 -90
wait 0.2
# ⚠️ **Every hold in this file is short and the acts do not overlap.** A `hook` line holds the
# button for its whole duration, and a second `hook` on the SAME arm inside that window is not
# an edge — it fires nothing, silently, and the act that follows then measures the previous
# act's rope. That cost two runs: ACT 3 reported `rope == 1` about ACT 2's pavement anchor
# while the titan was never hooked at all. Each act therefore ends with a gap long enough for
# its own arm to come home.
hook left 5.0
wait 0.4
mark q078-hooked-the-pavement-under-his-feet
assert rope == 1
assert speed > 15.0      # 21.323 — gravity plus the rope, both pointing down
assert speed < 75.0      # vector.max_speed_m_s. THE guard, and it is not close
key Ctrl 3.0
wait 3.0
mark q078-reeled-into-the-street
assert rope == 1
assert speed < 1.0       # 0.000 — reeling into the floor is a dead stop, not a launch
assert height > 1.0      # 1.500 — the pavement, and he is standing ON it
assert height < 2.0

wait 1.5                 # the left arm comes home before ACT 2 asks it for an edge

# ---- ACT 2: hook the ground while already falling at 46 m/s ----------------------------
#
# The same rope, entered at speed. He falls 1.4 s from 120 m (**45.9 m/s**), fires straight
# down, anchors on the same pavement 8 ticks later, and keeps accelerating: **53.3 m/s** two
# ticks after the shot, **60.8 m/s** two ticks after that. The rope is slack the whole way —
# he is falling TOWARDS his own anchor — so nothing here is the rope, it is g.
#
# The reading that matters is the one that is NOT here: at no point does the number pass
# **75.000**, and an earlier pass that fell from 90 m read exactly `75.000` and stayed there.
# `max_speed_m_s` is a hard clip, not a soft target.
warp 168.19 120.0 -50.12
look 0 -90
wait 1.4
mark q078-falling-before-the-shot
assert speed > 40.0      # 45.866
assert speed < 75.0
hook left 2.0
wait 0.4
mark q078-hooked-the-ground-at-speed
assert rope == 1
assert speed > 50.0      # 60.798, and still only gravity
assert speed < 75.0      # ★ THE CLAMP. Nothing in this file has ever exceeded it
wait 1.0
mark q078-arrived
assert rope == 1
assert speed < 1.0       # 0.000 — he is on the street
assert height < 2.0      # 1.500

wait 1.5                 # and again: ACT 3's left shot needs a fresh edge

# ---- ACT 3: a rope on a WALKING TITAN and a rope on a roof, pulling apart ---------------
#
# `F-029 Dynamische Ankerpunkte` arrived as a side effect of Q-078 (a titan's root capsule
# carries `SOLID | ANCHORABLE`), and it is the one genuinely new case: **a moving constraint
# against the `DistanceJoint` that landed the same day** (`F-005`, commit 7bb61cd).
#
# The geometry is `scripts/f029-grapple.txt` ACT 1's, because it is the one that is proven to
# find a titan instead of a roof beside him: 14 m off a husk who is well inside his
# `aggro_radius_m`, in the sky, so nothing else is in the crosshair. The SECOND rope then goes
# straight down into the city 46 m below — which is where the two anchors start pulling apart,
# one of them walking and one of them a building.
#
# Measured: left on body 2902 (the titan) at (58.73, 62.99, 0.00), right on body 150 (a roof)
# at (56.11, 4.21, -1.00). Over the next 5.5 s, with the husk walking the whole time:
#
#   t=192   rope 2   speed 12.547   height 50.278
#   t=284   rope 2   speed  3.580   height 50.318
#   t=406   rope 2   speed  1.698   height 50.347
#   t=528   rope 2   speed  4.128   height 50.308
#
# **7 cm of height drift in 5.5 s, both ropes alive, speed under 5 m/s.** A moving anchor
# against a static one does not resonate, does not fling and does not break the joint. That is
# the answer to the open question in Q-078, and it is a measurement rather than an argument.
spawn titan husk 60 60 0
warp 46 63 0
look -90 0
wait 0.30
hook left 8.0
wait 0.40
mark q078-hooked-a-walking-titan
assert rope == 1
assert speed < 75.0      # 23.823 — he was falling when he fired
look 0 -90
wait 0.30
hook right 8.0
wait 0.60
mark q078-and-a-roof-46-m-below
assert rope == 2
assert speed < 75.0      # 12.547
assert height > 45.0     # 50.278 — the two ropes caught him
wait 1.5
mark q078-two-carriers-1.5s-apart
assert rope == 2
assert speed < 10.0      # 3.580 — the swing is dying, not growing
assert height > 45.0     # 50.318
wait 2.0
mark q078-two-carriers-3.5s-apart
assert rope == 2
assert speed < 10.0      # 1.698
assert height > 45.0     # 50.347
wait 2.0
mark q078-two-carriers-5.5s-apart
assert rope == 2
assert speed < 10.0      # 4.128 — five and a half seconds, no resonance
assert height > 45.0     # 50.308 — 7 cm of drift while the anchor walked
assert height < 56.0

# `end` — the last instruction is an assert, and without this the run reports itself cut off
# at whatever `--ticks` says while every assert has already held.
#
# ⚠️ **And `end` alone is not enough: a run is finished only when nothing is still HELD**
# (`src/debug/mod.rs`, `run.at >= run.plan.len() && run.held.is_empty()`). Both ACT 3 holds are
# therefore 8.0 s and not 12.0 — long enough to carry the last assert at t=1106, short enough
# that the button is up before the tick limit. A 12 s hold reported "did not finish" at
# --ticks 1400 with all 30 asserts already green.
end
