# F-031 — GESCHWINDIGKEITSABHAENGIGE SCHADENSFORMEL: three body passes floor a husk, and the
# fourth pass takes his nape.
#
#   ./target/debug/defeated_by_titan --headless --script scripts/f031-damage.txt --ticks 700
#   ./target/debug/defeated_by_titan --headless --script scripts/f031-damage.txt --ticks 700 >/dev/null 2>&1; echo $?
#
# ## What had to exist before this run could say anything
#
# `gear.ron: blades.damage_per_m_s = 1.4` had **no reader anywhere in `src/`** until 2026-08-25,
# and `titan::rig`'s `Health::full(titan.ron: husk.health = 100)` had **no writer**. A number on
# one side, a pool on the other, and nothing in between — the same shape `docs/FINDINGS.md`
# FIND-075 records for `wear_per_hit`.
#
# The lines to grep for — **re-measured 2026-08-29 after the gravity re-derivation**:
#
#   tick 131: titan 1 took 28.4 in the Torso   at 20.3 m/s (x1.00) — pool 72/100
#   tick 138: titan 1 took 33.2 in the LegLeft at 22.9 m/s (x1.15) — pool 38/100
#   tick 189: titan 1 COLLAPSED — 54 ticks on the floor, 240 of refractory
#   tick 291: cut titan 2 Cortex at 20.27 m/s
#
# **28.4 is `1.4 x 20.27 x 1.00`** and **33.2 is `1.4 x 22.93 x 0.9 x 1.15`** —
# `damage_per_m_s` x the closing speed x `zone_limb_factor` x the combo multiplier. Every one of
# the seven damage lines this run prints closes to the last digit on that formula; it is the
# formula and not the numbers that is the claim here.
#
# ⚠️ **Two things in this block moved for reasons that are NOT gravity, and neither is this
# file's to fix.** (a) A pass now books TWO zones where the 2026-08-25 run booked one — the limb
# boxes carry colliders today and `Torso`/`LegLeft`/`ArmLeft` are all produced, which
# `scripts/f032-swords.txt`'s 2026-08-19 table says was not true then. (b) The husk therefore
# COLLAPSES during pass **2** and not pass 3. The asserts do not care — they claim only that a
# body cut never kills — but the header used to promise pass 3 and now it does not.
#
# ## 🔴 WHERE THE HEIGHTS AND THE WAITS COME FROM — DERIVED, NOT AIMED
#
# The pass speed is the constant and gravity decides the rest. The full derivation lives in the
# header of `scripts/f030-cortex.txt`; the two lines this file needs out of it are
#
#     drop   = v² / (2 g)  = 21² / 64 = 6.891 m       g = -game.ron: gravity_m_s2 = 32
#     wait   = v / g - 0.15                = 0.506 s   (0.15 = the middle of the blade's
#                                                       active window, gear.ron 0.08..0.22)
#
# and the nape warp is `cortex_height_m 17.80 - eye_height_m 1.60 + drop` = **23.091**.
# PINS: the pass speed at the nape (21.0 m/s). Warp heights and x offsets follow from it and
#       from the geometry; re-derived 2026-08-29 for the doubled classes and for the neck
#       (`titan::rig::body_segments_m`) — the body cuts are flown at x offset 2.50 because at
#       chest height the clearance is the TORSO (2.00 + 0.35), not the neck.
# The control: feed g = 20 back in and it prints `wait 0.900` and `drop 11.03 m`, which is the
# calibration this file shipped with. **When gravity moves again, re-evaluate those two lines —
# do not re-aim by hand.**
#
# ## Why the passes start 3 m lower than `f030-cortex.txt`
#
# That file starts at y = 14.19 and its blade meets the **nape** at 8.9 m. Three metres lower is
# the chest: above `leg_m` 4.80 and well under a 0.55 m cortex sphere that `thickness_m` 0.20
# cannot bridge. So these are BODY cuts by construction, and the last act — back at 14.19 — is
# the control that says the same geometry still kills when it is aimed at the nape.
# **The `-3.00` is the whole relationship and it is what survives a gravity change**: both warps
# are `nape warp - 3.00`, so the two acts stay exactly three metres apart on the husk whatever
# `drop` evaluates to. 14.19 - 3.00 = **11.19**, and the crossing is the same point on the body
# it always was (eye at 5.90 m, `leg_m` 4.80 .. cortex 8.90).
#
# 🔴 **Emptying the pool is not a kill and this run is what shows it.** `assert titans == 1`
# stands after every body pass; the husk is only ever gone after the pass that reaches his
# cortex. If a damage formula ever becomes a second way to kill, those asserts are what fall.
#
# ⚠️ The husk aggros and strikes for 34 of the player's 100 (`titan.ron: husk.damage`), so the
# player may well be down by the last act. That costs nothing here: `warp` works on a downed
# player and the blade still swings.
wait 1.5
spawn titan husk 17.5 0 0
look 0 0
key F3 0.05

# --- pass 1: the chest, at 20.27 m/s -------------------------------------------------
warp 15.000 17.091 1.35
wait 0.506
slash right 0.40
wait 0.30
mark body-pass-1
assert titans == 1

# --- pass 2 --------------------------------------------------------------------------
warp 15.000 17.091 1.35
wait 0.506
slash right 0.40
wait 0.30
mark body-pass-2
assert titans == 1

# --- pass 3: the pool should be empty around here, and he goes on the floor -----------
warp 15.000 17.091 1.35
wait 0.506
slash right 0.40
wait 0.30
mark body-pass-3
assert titans == 1

# --- pass 4: the same geometry, aimed at the NAPE, on a husk that has NOT been fought yet.
#
# 🔴 **It has to be a fresh husk, and that is measured and not tidiness.** (The run below is the
# 2026-08-25 one, at `gravity_m_s2` −20 — its `y = 18.5` and `20.67 m/s` are that calibration's
# numbers, not today's 14.19 and 20.27. **The conclusion is about the titan's FACING and does not
# depend on either.**) The first version of
# this act warped back to the husk above and cut at x = 15.75 / y = 18.5 — `scripts/f030-cortex.txt`
# to the centimetre — and booked `Torso` at 20.67 m/s, never a nape. The control that settles it
# was one run: `f030-cortex.txt`'s own act with a bare `wait 4.0` inserted before the warp, same
# spawn, same warp, same slash. Fresh: `cut titan 1 Cortex at 20.67 m/s`, dead. After four
# seconds of aggro: `cut titan 1 Torso at 20.67 m/s`, alive. Nothing else differed.
#
# **The husk turned to face the player, and `titan.ron: husk.cortex_half_angle_deg` refuses a
# cortex cut from the front by rule** (`Q-030`/`Q-031`, `src/blades/cut.rs:214`). So the nape is
# not a fixed point in space after the fight has started — it is behind a titan who is looking at
# you, and any script that aims at it six seconds in is aiming at a chest.
#
# 60 m up the −Z axis, which is outside `titan.ron: husk.aggro_radius_m` (45) from where the
# player stands, so this one is asleep until the warp — the same 0.506 s of lead the fresh pass in
# `f030-cortex.txt` gets, and not a tick more. (0.9 s at `gravity_m_s2` −20; the two files are
# still the same lead because both read it off the same derivation.)
spawn titan husk 17.5 0 -60
# `titan::spawn_titans` runs in `PostStep`, so the body stands at the end of the NEXT tick — an
# assert on the same line as the spawn reads 1 and says nothing about the spawn.
wait 0.10
assert titans == 2
warp 15.800 23.091 -58.65
wait 0.506
slash right 0.40
wait 0.08
mark cortex-cut
wait 0.10
# The one that carries the whole claim: three body passes emptied a pool TWICE over and the husk
# they were flown at is still standing. Only the nape is a kill.
assert titans == 2
wait 1.20
assert titans == 1
