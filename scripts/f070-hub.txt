#
# ⚠️ **Two runs, two `--ticks`, and the second number is not a typo.** The screenshot is taken
# at the last tick of its run, so the picture has to be aimed at a moment: t = 1035 is halfway
# through ACT 3, inside the hall and looking back east at the open gate. That run reports red —

# exit 0 with red asserts in its own log. Raising the limit is free; lowering it turns a green
# feature red for a reason that is not in the game.
#
# ---------------------------------------------------------------------------------------
# WHAT THIS FILE CLAIMS — nine things, and every one of them is an `assert`
#
#   1. `--hub` starts the game **in the hub**, not in a fight        (`assert phase == 5`)
#   2. the main building is a building you **walk into**             (`assert height > 0.10`)
#   3. gas comes back **inside it and nowhere else**                 (`assert gas`, twice, Q-033)
#   4. you **walk out** again through the same gate                  (`assert height < 0.10`)
#   5. walking onto a deployment pad **starts that pad's sortie**    (`assert phase == 2`)
#   6. the sortie can be **won**                                     (`assert kills`, `phase == 3`)
#   7. and a won sortie **lands you back in the hub**                (`assert phase == 5`)
#   8. **fighting blunts the blades** and the wear survives the debrief (`assert sharpness < 0.80`)
#   9. and the racks **hone them back** when he walks in a second time (`assert sharpness > 0.99`)
#
# ⚠️ **8 and 9 are one claim in two halves, and the order is the whole point.** Until 2026-08-13
# this file asserted `blades == 5` at the rack in ACT 2 and called it "the harness is full" — a
# tautology twice over (`docs/FINDINGS.md` FIND-079): it fired at t≈865, some 900 ticks before the
# first titan even exists, and `blades` counts **spare pairs**, of which a whole sortie spends
# none. `sharpness` is the metric that moves. So the file now **cuts first and walks in after**:
# two cortex kills cost `gear.ron: blades.wear_per_hit` 0.12 each, he carries **0.760 — measured,
# 2026-08-13** back into the hub, and ACT 7 walks him to the racks to get it back. Neither half
# can pass without the other having happened, and both halves have been watched going red
# (a run with the two `slash` lines removed reads 1.000 at ACT 6; a run whose ACT 7 turns EAST
# instead of west reads 0.760 at the rack).
#
# ⚠️ **0.24 and not 0.36: this fall-cut books ONE hit per pass, the cortex one.** `blades::cut`
# charges a torso graze `× wear_torso_factor` on top *when the blade passes the body as well*,
# and `src/blades/cut.rs`'s own budget test adds the two up. The arranged pass of ACT 5 reaches
# 0.15 m into the cortex sphere from 1.75 m to the side and never touches the torso capsule, so
# a script kill is cheaper than a fought one. That is why the bound is `< 0.80` and not `== 0.64`.
#
# The phase numbers are `mission::MissionPhase::code`, and 5 was appended and took nobody's
# number: 0 Briefing · 1 Deploying · 2 Active · 3 Won · 4 Lost · **5 Hub**.
#
# ---------------------------------------------------------------------------------------
# THE GEOMETRY — and why `height` is the only thing that can say "inside"
#
# The script language measures `height` and cannot measure x or z. It does not have to: the
# depot floor of the garrison headquarters is at **0.15 m and it is the only 0.15 m floor in
# `maps.ron: ashgate`** — the ground is 0.0, every apron 0.05, the quays and bridges 0.4. So
#
#     assert height > 0.10   means INSIDE the main building, and nothing else satisfies it
#     assert height < 0.10   means OUT on the pavement
#
# and a run that shows 0.05 → 0.15 → 0.05 has walked in through the gate and back out of it,
# because the gate is the only gap in the facade (`tests/world.rs::
# f019_the_headquarters_doorway_is_a_gap_a_player_really_fits_through` sweeps a 0.35 m capsule
# through all 1.5 m of the wall to say so).
#
#   the hall        x = -45.5 .. -16.5   |z| <= 11.5   29 x 23 m, 10 m in the clear
#   the gate        x = -16.5 .. -15     |z| <= 3      6 m wide, 4.5 m to the lintel
#   the two racks   (-42, 0.15, -2.0) gas · (-42, 0.15, 2.0) blades — the racks' AISLE FACES,
#                   reach 4.0 m out of `gear.ron: resupply.range_m`
#   the spawn point (0, 2, 0), 15 m in front of the gate and looking at it
#
# ⚠️ **The stations sat at the racks' CENTRES until 2026-08-13 and the walk did not work**
# (`docs/FINDINGS.md` FIND-075): a rack is 5 x 9 m of collider, so a trigger in its middle left
# 57 standable cells inside the reach — a 1.15 m strip between the rack and a roof post, and a
# 1.0 m slot behind it. This file's ACT 2 used to be a `warp -38.75 1.0 -6.0` into that strip,
# and a warp is exactly the evidence a supply point must not need. `tests/mission.rs::
# f019_walking_straight_down_the_aisle_puts_you_in_reach_of_every_rack` is the criterion now.
#
# `look 90 0` faces WEST and `look 270 0` faces EAST: `forward = (-sin yaw, 0, -cos yaw)`. That
# sign cost `scripts/f-flight-cut.txt` nine red asserts once, so it is spelled out here too.
# `game.ron: player.run_speed_m_s` is 6.0, so `key W 9.0` is 54 m of intent against 45 m of
# floor — the walk ends at a wall in both directions, which is what makes it reproducible
# without arithmetic.
#
# ---------------------------------------------------------------------------------------
# ⚠️ WHAT THIS FILE DOES **NOT** CLAIM
#
# - **NOT that the racks hand out a fresh PAIR.** `blades` never leaves 5 in this run and it is
#   not supposed to: two kills cost 0.24 of one pair's sharpness and a spare is only drawn when a
#   pair is spent to zero, which takes eight of these cuts. What ACT 7 proves is the
#   **honing** (`gear.ron: resupply.sharpen_per_s` 2.0). The pair *counter* going back up is
#   proven where a harness can be emptied first, which a script cannot do:
#   `tests/mission.rs::f033_a_player_at_a_rack_of_the_hub_walks_away_restocked`.
# - **Not a cut a human could land.** The two kills are the fall-cut of
#   `scripts/f030-cortex.txt`, arranged by arithmetic: `warp` to 18.5 m, fall, and the blade
#   passes a husk standing 1.75 m to the side. Both husks are **spawned by the script**, and
#   that is honest rather than convenient: a wave titan stands on a 24 m ring and no script can
#   aim at one. What the mission counts is a cortex kill, and it does not care who put the
#   titan there.
# - **Not the difficulty being felt.** `recruit` was chosen because it needs two kills; that the
#   three levels differ is `tests/mission.rs::
#   f072_the_difficulty_and_not_the_template_decides_the_numbers`, not this run.
# - **Not multiplayer.** One player walks onto the pad and one squad deploys. The rule that any
#   player deploys everyone is written down in `mission::hub` and has never had two players
#   standing in a hub to prove it.

# =========================================================================================
# ACT 5 — the sortie. Two cortex cuts, out of a fall, exactly as scripts/f030-cortex.txt.
# =========================================================================================
#
# Why the player falls instead of flies: `gear.ron: blades.min_speed_m_s` is 8.0 and a running
# player does 6.0, so a cut needs speed the legs cannot give. Gravity can, and it is
# reproducible to the tick — 11.2 m of fall is 21 m/s. Why x = 15.75: the husk's body capsule
# is 1.25 m and the player's 0.35 m, so 1.75 m to the side is 0.15 m of air, and the 1.6 m
# blade reaches 0.15 m into a cortex sphere centred on x = 17.5.

# ⚠️ The 0.90 between the warp and the slash is the fall, and it is **not adjustable**: the
# first version of this file put an `assert titans == 1` and a `wait 0.1` in between, the player
# fell one tenth of a second further, and the blade went past under the nape. The husk lived,
# the mission was never won, and nothing in the log said "you missed" — it said `titans == 1`.
# Whoever adds a line inside this block moves the cut.
#
# ⚠️ **THE DROP HEIGHT IS DERIVED, NOT MEASURED — re-derive it when `gravity_m_s2` moves.**
# `wait 0.90` fixes the FALL TIME, so the height the blade meets the nape at is whatever
# gravity has done to the player in that time. The cut must land on the cortex, so the warp
# height is the unknown and the formula is free fall:
#
#     h0 = h_cut + 0.5 * |gravity_m_s2| * t_fall^2
#
#     t_fall = 1.0334 s   the script's own `wait 0.90` plus the blade's 8-tick windup, and it
#                         is GRAVITY-INDEPENDENT: the Cortex cut lands on tick 458 at -20 and
#                         on tick 458 at -32, measured 2026-08-29
#     h_cut  = 7.82 m     where the blade meets the nape, read off the g = -20 run that this
#                         file was calibrated against (20.67 m/s at the cut / 20 = 1.0335 s)
#
#     |g| = 32:  h0 = 7.82 + 0.5*32*1.0334^2 = 7.82 + 17.09 = 24.91  ->  **24.9**, used below
#     |g| = 20:  h0 = 7.82 + 0.5*20*1.0334^2 = 7.82 + 10.68 = 18.50  ->  the committed value
#                                                                       this file used to hold
#
# The second line is the control: the formula REPRODUCES the old number at the old gravity, so
# it is a derivation and not a re-fit. Measured window at -32: every h0 in 24.0..27.0 kills;
# 23.0 does not. `gravity_m_s2` went -20 -> -32 on 2026-08-27 and is PROVISIONAL — when the
# user moves it again, evaluate the line above, do not re-measure the file.
spawn titan husk 17.5 0 0
warp 15.75 24.9 0.8
look 0 0
wait 0.90
slash right 0.40
wait 0.18
assert titans == 1    # the blade is through him and the body is still dissolving
wait 1.20
assert titans == 0    # death_s 1.0: the body is gone a second after the nape was cut
assert kills == 1     # ⭐ and the MISSION counted it
mark f072-first-kill

spawn titan husk 17.5 0 0
warp 15.75 24.9 0.8
look 0 0
wait 0.90
slash right 0.40
wait 1.45
