# F-030 — **the hitbox, measured as a cushion.** One nape pass per spawnable kind, every one of
# them flown with **0.60 m of air between the two capsules**, and every one of them has to kill.
#
#   nice -n 15 cargo run -q -- --headless --script scripts/f030-hitbox.txt --ticks 1600
#
# and, as a SEPARATE run, the one that returns a usable exit code:
#
#   ./target/debug/defeated_by_titan --headless --script scripts/f030-hitbox.txt --ticks 1600 \
#     >/dev/null 2>&1; echo $?
#
# ⚠️ A `--screenshot` run is not a verdict (`docs/FINDINGS.md` FIND-073): the screenshot system
# owns the ending and exits 0 without ever reading `run.failures`. Only `--headless` prints
# "N asserts held".
#
# ## What this file measures, and why it is a CUSHION and not a standoff
#
# `docs/FINDINGS.md` FIND-147: the term that decides whether a nape is reachable is not
# `cortex_radius_m`. It is
#
#     band = reach_m + thickness_m + cortex_radius_m − body_radius − player_radius
#
# and `body_radius` is `scale.ron: width_fraction 0.25 × height / 2`, which grows with the class
# three times faster than the cortex does. So the numbers that matter are **per kind** and a
# single absolute standoff would be meaningless: 1.85 m is a comfortable pass at a husk and
# inside a warden's shoulder.
#
# Every act below therefore flies at
#
#     x = −(body_radius + player_radius + 0.60)      body_radius = 0.125 × height_m
#
# i.e. with **0.60 m of empty air between the player's capsule and the titan's**. That is a
# cushion a player can hold at 21 m/s (0.35 m per tick), not the last centimetre of a clearance.
# **If a kind cannot be killed from 0.60 m of air, that kind's hitbox does not fit.**
#
# ## 🔴 WHERE THE SEVEN LANES STAND, and it changed on 2026-08-29
#
# They stood at `z` 0.55, 200.55, **400.55, 600.231, 800.231, 1000.77 and 1200.77** — and
# Ashgate is 700 x 700 m, so five of the seven were outside the map, the last one 850 m out.
# `F-012`'s recovery teleported the player home on the next tick, **six times per run**, and
# because no act here asserts a position the file went on measuring a player who had been moved:
# every act from `chorus` onward was flown from `(-2.20, 2.00, 200.55)`, the errant act's ground.
#
# The seven lanes now run along the **boulevard** `(0, -0.1, -83.75) x (700, 0.3, 27.5)` — a
# cleared paved strip across the full width of the district, no house on it and no terrace over
# it. Probed 2026-08-29 at x = -300, -200, -100, 0, 100, 200 and 300: the resting height is
# **0.050 m at every one of the seven**, which the old z-lanes were not.
#
# ⚠️ **Not one number in a pass changed.** Every titan still spawns at `y = 0`, every player
# warp keeps its absolute height and its `x` cushion and its `z` set-back relative to the
# titan; the lane is a rigid translation of both. Lane spacing is 100 m — every act ends with
# `assert titans == 0`, so nothing survives to walk into the next one, and the warden's two
# passes share a lane on purpose.
#
# ## Why the player falls instead of flying
#
# Same reason as `scripts/q030-reach.txt` and `scripts/f030-cortex.txt`: hooking and boosting
# cannot be aimed from a script accurately enough to pass a 1.10 m sphere, and gravity can. Every
# act drops **11.2 m** at −20 m/s², which is 21.0 m/s at the nape and reproducible to the tick.
# The warp height is therefore `cortex_height_m − eye_height_m 1.60 + 11.2`:
#
#     small  (4.2 m, cortex 3.7)   13.30      body_radius 0.525   x −1.475   z 0.231
#     medium (10 m,  cortex 8.9)   18.50      body_radius 1.250   x −2.200   z 0.550
#     large  (14 m,  cortex 12.5)  22.10      body_radius 1.750   x −2.700   z 0.770
#
# `z` is `head_m / 2` = `0.055 × height_m`, the cortex's set-back behind the neck axis
# (`src/titan/rig.rs::cortex_in_head`) — standing on it puts the blade's line through the
# sphere's centre, so the only thing being measured is the lateral cushion.
# ⚠️ That `z` is a SET-BACK and not a radius. On a husk it is 0.55 and `cortex_radius_m` is also
# 0.55 today; the two are different numbers that happen to coincide, and they diverge the moment
# either moves.
#
# ## Why the titan is spawned 0.20 s before the cut
#
# Because a titan turns toward you at `turn_deg_per_s` in Pursue **and** in Windup, and the nape
# sits half a head's depth behind his axis — so every second of lead carries the nape out of the
# blade's line (FIND-147: the husk's measured band narrows from 65 cm at 0.05 s of lead to 25 cm
# at 0.60 s). A pass flown 1.0 s after the spawn measures the titan's neck rotation, not the
# hitbox. 0.20 s is one wind-up's worth of notice and no more.
#
# ## The control (rule 5)
#
# Delete every `slash` line and this file reports **7 failed** and not one `cut titan` line of any
# zone — so it measures the blade and not a titan walking into a falling player. Run it that way
# before believing a green.
