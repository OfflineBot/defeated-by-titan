# F-030 — **the hitbox, measured as a cushion.** One nape pass per spawnable kind, every one of
# them flown with **0.60 m of air between the two capsules**, and every one of them has to kill.
#
# PINS: the pass speed at the nape (21.0 m/s) AND the 0.60 m of air between the two capsules.
#       Warp height, fall time and the x offset all follow from those two. When a class height,
#       `gravity_m_s2` or `titan::rig::body_segments_m` moves, the three numbers below move and
#       the speed and the cushion do NOT.
#
#   nice -n 15 cargo run -q -- --headless --script scripts/f030-hitbox.txt --ticks 1600
#
# and, as a SEPARATE run, the one that returns a usable exit code:
#
#   ./target/debug/defeated_by_titan --headless --script scripts/f030-hitbox.txt --ticks 1600 \
#     >/dev/null 2>&1; echo $?
#
# ⚠️ A `--screenshot` run is not a verdict (`docs/FINDINGS.md` FIND-073): the screenshot system
# owns the ending and exits 0 without ever reading `run.failures`. Only `--headless` prints
# "N asserts held".
#
# ## What this file measures, and why it is a CUSHION and not a standoff
#
# `docs/FINDINGS.md` FIND-147: the term that decides whether a nape is reachable is not
# `cortex_radius_m`. It is
#
#     band = reach_m + thickness_m + cortex_radius_m − clearance − player_radius
#
# ⚠️ **`clearance` used to be `width_fraction 0.25 × height / 2` and that was the defect**, not
# the formula: it is the SHOULDER, and the shoulder is not what a blade meets at the nape. Since
# 2026-08-29 the body is a torso capsule ending at the shoulder plus a neck at the head's own
# width, and the clearance is `TitanRig::widest_between_m` over the player's own 1.8 m. So the
# numbers that matter are still **per kind** and a single absolute standoff would still be
# meaningless.
#
# Every act below therefore flies at
#
#     x = −(clearance + player_radius + 0.60)
#
# i.e. with **0.60 m of empty air between the player's capsule and the titan's**. That is a
# cushion a player can hold at 21 m/s (0.35 m per tick), not the last centimetre of a clearance.
# **If a kind cannot be killed from 0.60 m of air, that kind's hitbox does not fit.**
#
# ## 🔴 WHERE THE SEVEN LANES STAND, and it changed on 2026-08-29
#
# They stood at `z` 0.55, 200.55, **400.55, 600.231, 800.231, 1000.77 and 1200.77** — and
# Ashgate is 700 x 700 m, so five of the seven were outside the map, the last one 850 m out.
# `F-012`'s recovery teleported the player home on the next tick, **six times per run**, and
# because no act here asserts a position the file went on measuring a player who had been moved:
# every act from `chorus` onward was flown from `(-2.20, 2.00, 200.55)`, the errant act's ground.
#
# The seven lanes now run along the **boulevard** `(0, -0.1, -83.75) x (700, 0.3, 27.5)` — a
# cleared paved strip across the full width of the district, no house on it and no terrace over
# it. Probed 2026-08-29 at x = -300, -200, -100, 0, 100, 200 and 300: the resting height is
# **0.050 m at every one of the seven**, which the old z-lanes were not.
#
# ⚠️ **Not one number in a pass changed.** Every titan still spawns at `y = 0`, every player
# warp keeps its absolute height and its `x` cushion and its `z` set-back relative to the
# titan; the lane is a rigid translation of both. Lane spacing is 100 m — every act ends with
# `assert titans == 0`, so nothing survives to walk into the next one, and the warden's two
# passes share a lane on purpose.
#
# ## Why the player falls instead of flying
#
# Same reason as `scripts/q030-reach.txt` and `scripts/f030-cortex.txt`: hooking and boosting
# cannot be aimed from a script accurately enough to pass a 1.10 m sphere, and gravity can.
#
# 🔴 **THE DROP AND THE WAIT ARE DERIVED FROM `game.ron: gravity_m_s2`. NEVER RE-AIM THEM BY HAND.**
# The constant is the SPEED at the nape — 21.0 m/s, which clears `gear.ron: blades.min_speed_m_s`
# 8.0 and `feel.strong_hit_m_s` 18.0, and which is the 0.35 m per tick this file's whole cushion
# argument is written against. Off that one number and gravity:
#
#     g      = -game.ron: gravity_m_s2  = 32.0 m/s²
#     drop   = v² / (2 g)  = 441 / 64   = 6.891 m       (was 11.2 m at g = 20)
#     t_fall = v / g       = 21 / 32    = 0.656 s       (was 1.05 s)
#     wait   = t_fall - (active_from_s 0.08 + active_to_s 0.22) / 2 = 0.506 s from warp to slash
#
# and the last one is split `wait 0.446` / `spawn` / `wait 0.06` so the titan gets 0.06 + 0.15 =
# **0.21 s of lead**, which is the number the section below argues for. **Control: g = 20 back in
# prints `drop 11.03 m` and `warp to slash 0.900 s` — the calibration this file shipped with, so
# the formula is a derivation of it and not a fresh aim.**
#
# The warp height is therefore `cortex_height_m − eye_height_m 1.60 + drop`:
#
# 🔴 **THE WHOLE TABLE MOVED ON 2026-08-29, TWICE OVER, AND NEITHER MOVE WAS A RE-AIM.**
#
# First, `scale.ron`'s five classes DOUBLED on the user's word (*„die aktuellen sind eher kleiner!
# gerne doppelt so gross oder so"*), and with them every `cortex_height_m` and every
# `titan.ron: cortex_radius_m`. Second, and this is the one that changes the meaning of the `x`
# column: **the clearance is no longer `width_fraction × height / 2`.** A titan's physical body
# was one capsule of SHOULDER half-width running from the ankles to the crown; it is now a torso
# capsule that stops at the shoulder plus a neck at the head's own width
# (`titan::rig::body_segments_m`). So the number a pass has to clear at nape height is
# `TitanRig::widest_between_m(cortex_height_m − player.height_m, cortex_height_m) + 0.35`, which is
# the widest the body gets anywhere along the player's own 1.8 m — his knees are down among the
# shoulders while his eye is at the nape, and every fixture that wrote `width_m * 0.5` was
# answering a question about the shoulder.
#
#     class   height  cortex   warp y    clearance   x offset (+0.60)   z set-back
#     small    8.4      7.4    12.691      1.190        −1.790            0.462
#     medium  20.0     17.8    23.091      1.550        −2.150            1.100
#     large   28.0     25.0    30.291      1.890        −2.490            1.540
#
# ⚠️ `width_fraction` also moved, 0.25 -> 0.20, because `0.25 x 28 m` is a 7.00 m body in a 6.0 m
# street and `tests/data.rs` says so out loud. It shrinks the `small` and `medium` clearances
# above and leaves `large` at 1.890 — because `large`'s clearance is the NECK, and the neck is a
# function of `head_m` and not of the shoulders.
#
# `clearance` is the shoulder for `small` (0.84 m: an 8.4 m titan's shoulder is only 0.92 m below
# his nape, so a 1.8 m player still hangs into it), the shoulder's cap for `medium`
# (1.20 m, 1.6 m above the capsule's top endpoint) and the NECK for `large` (1.54 m, where the
# player fits entirely into the pocket between the shoulders and the head). **That is the whole
# fix: the bigger the titan, the more room there is at his neck** — which is why the size the
# user asked for and the reach he asked for are one change and not two.
#
# ⚠️ **`x` and `z` are not functions of `g`.** They are the lateral cushion and the cortex's
# set-back; gravity touches neither. They moved on 2026-08-29 because the class table doubled and
# the body grew a neck, and for no other reason. Only the height column and the wait are
# functions of `g`.
#
# `z` is `head_m / 2` = `0.055 × height_m`, the cortex's set-back behind the neck axis
# (`src/titan/rig.rs::cortex_in_head`) — standing on it puts the blade's line through the
# sphere's centre, so the only thing being measured is the lateral cushion.
# ⚠️ That `z` is a SET-BACK and not a radius. On a husk both are 1.10 m today; they are different
# numbers that happen to coincide, and they diverge the moment either moves.
#
# ## Why the titan is spawned 0.20 s before the cut
#
# Because a titan turns toward you at `turn_deg_per_s` in Pursue **and** in Windup, and the nape
# sits half a head's depth behind his axis — so every second of lead carries the nape out of the
# blade's line (FIND-147: the husk's measured band narrows from 65 cm at 0.05 s of lead to 25 cm
# at 0.60 s). A pass flown 1.0 s after the spawn measures the titan's neck rotation, not the
# hitbox. 0.20 s is one wind-up's worth of notice and no more.
#
# ## The control (rule 5)
#
# Delete every `slash` line and this file reports **7 failed** and not one `cut titan` line of any
# zone — so it measures the blade and not a titan walking into a falling player. Run it that way
# before believing a green.
#
# ## 🔴 WHERE THIS FILE STOOD BEFORE 2026-08-29, and what the doubling did to it
#
# It ran 8 asserts green at the OLD sizes — but green was hiding the measurement. Swept tick by
# tick at the shipped cushion, the nape was open for
#
#   scuttler 1 · weaver 1 · chorus 2 · errant 2 · husk 3 · lurker 3 · warden 3   ticks (21 m/s)
#
# and `tests/titan.rs::f030_the_nape_is_hittable_for_more_than_one_tick_on_every_spawnable_kind`
# is where that sweep now lives. **One tick is not a hitbox, it is a coincidence** — a single
# green pass per kind cannot tell a 1-tick window from an 11-tick one, and this file was reporting
# 8 of 8 while five of seven kinds were inside three ticks. After the doubling and the neck:
#
#   scuttler 3 · weaver 3 · chorus 7 · errant 7 · husk 8 · lurker 11 · warden 11
#
# ⚠️ The two `small` kinds are at 3 and the derived floor is 3. The missing centimetres are
# `gear.ron: blades.thickness_m`, which is **0.20** while its own comment in the same file argues
# for 0.30 four times over (`docs/FINDINGS.md` FIND-213). At 0.30 the small class is at 4.
#
