# f-018-gas — the tank empties at exactly the rate the file names, then stops, then fills back.
#
#   the verdict:  cargo run -q -- --headless --script scripts/f-018-gas.txt --ticks 1500
#   the picture:  cargo run -q -- --offscreen --script scripts/f-018-gas.txt --ticks 1118 \
#                     --screenshot docs/images/f-018-gas.png
#
# ⚠️ **TWO DIFFERENT TICK COUNTS, and the verdict's is not free to choose.** The verdict needs
# a number ABOVE the script's own end (measured: it finishes at t=1362) or the run is cut off
# and `--ticks` exits 0 without the assert summary ever printing. The picture is shot at the
# tick of `f018-dry`, **1118**, because `--screenshot` fires at `--ticks` and shooting at 1500
# writes nothing at all — the process is already gone.
#
# ⚠️ **1118 used to be forced for a second reason that is now void.** It read "the tank does
# not stay empty: the closing `wait 3` puts 30 gas back at 10/s". Since Q-033 (see ACT 4) the
# tank stays at 0.300 to the end of the run, so any tick from 1118 to 1362 photographs the
# same empty bar. 1118 is kept because `docs/images/f-018-gas.png` was shot there and an image
# whose tick moves is an image whose diff means nothing.
#
# ⚠️ WHAT THE IMAGE SHOWS NOW: `src/hud/gas_bar.rs` is no longer a stub, so at t=1118 the bar
# in the bottom left is drawn EMPTY — the same claim as `assert gas < 0.3`, in pixels. That
# sentence used to read "this image does not show the gas level"; it did not since the HUD job.
# The camera is against a house wall: seventeen seconds of boost at `look 0 -10` carry the
# player into the city, and this file measures a tank, not a view.
#
# The point of this run is the ARITHMETIC, and the arithmetic is done by the `assert` lines,
# not by a human reading a bar. `assert gas` measures `Gas::current` of the local player
# (src/debug/mod.rs), and every value below is computed from assets/data/game.ron alone:
#
#   gas_tank          = 300   (was 100 until 2026-08-10 — docs/QUESTIONS.md Q-033)
#   gas_boost_per_s   =  18   -> 0.3    per tick at 60 Hz
#   gas_reel_per_s    =   6   -> 0.1    per tick at 60 Hz
#
#   there is NO gas_regen_per_s and NO gas_regen_delay_s. They existed on 2026-08-10, this
#   file measured them, and the user deleted the mechanism with Q-033: „gas refillt nur im
#   main gebäude". `game.ron` carries the ⚠️⚠️ block that says so; ACT 4 is the run that
#   would go red if they came back.
#
# A `key Shift <s>` holds the key for <s> seconds of FIXED time, so 1.0 is 60 ticks and 60
# ticks are 18 gas. If somebody multiplies by dt a second time, one tick costs 18/3600 =
# 0.005 instead of 0.3, the second assert below measures 299.7 instead of 282, and the run
# exits 1.
#
# ⚠️ **A `wait` IS FREE AGAIN, and the history of that sentence is the point of ACT 4.**
# Between 2026-08-10 and 2026-08-12 it was not: `vector::gas::refill_tank` put 10/s back
# during any tick in which nothing wanted gas, so every `wait` line below had to be accounted
# for and the pairing of `key Shift <s>` with `wait <s>` — the same seconds, the button down
# for every tick of the wait — was what kept the arithmetic of ACTS 2 and 3 honest.
#
# That pairing is kept, because it still says what it says: the boost costs 18/s for exactly
# as long as the button is down. But nothing puts gas back any more, so a `wait` no longer
# changes a tank. **Q-033 turned this file's hardest constraint into a free choice**, and the
# only place that still measures the difference is ACT 4.
#
# ⚠️ The brackets are ~0.35 wide, and that is not sloppiness — it is exactly ONE TICK of boost
# (0.3) plus a little. The driver counts a held key down in f32 (`run.held` in
# src/debug/mod.rs), and sixty subtractions of 1/60 do not land on exactly 0.0: measured
# [offlinebot], `key Shift 1.0` holds for 61 ticks and costs 18.300, not 18.000. A script
# that asserts to the tick is therefore flaky by construction; one that asserts to the tick
# +-1 measures the rate and nothing else.

wait 1.5                 # world, camera, meshes and the render pipelines come up
look 0 -10               # yaw along -Z (the axis contract), a little down: ground and houses

mark f018-tank-full
assert gas == 300        # game.ron: vector.gas_tank

# =========================================================================================
# ACT 2 — the rate. One second of boost is 18 gas and nothing else.
# =========================================================================================

key Shift 1.0            # one second of boost = 60 ticks x 0.3
wait 1.0
mark f018-one-second-of-boost
assert gas < 282.35      # 300 - 18, plus/minus the one tick above
assert gas > 281.65

key Shift 4.0            # four more seconds = 4 x 18 = 72
wait 4.0
mark f018-four-more-seconds
assert gas < 210.7       # 282 - 72, plus/minus one tick per `key` line so far
assert gas > 209.3

# =========================================================================================
# ACT 3 — and then it stops. **This act is twelve seconds long because the tank is 300.**
# =========================================================================================
#
# It was `key Shift 1.0` while the tank held 100: ten gas was not enough for a whole second
# and the act ran dry inside its own second. On a 300-tank the same line leaves 191 in the
# tank and asserts nothing at all — so the DURATION moved and the claim did not.
# 209.4 remaining / 18 per s = 11.63 s, and 12.0 s empties it with 0.37 s to spare.

key Shift 12.0
wait 12.0
mark f018-dry
assert gas >= 0          # a tank never goes negative
assert gas < 0.3         # and what is left over is less than one tick's cost: no half boost

# =========================================================================================
# ACT 4 — and it STAYS dry. A tank that only ever falls.
# =========================================================================================
#
# ⚠️ **RE-CUT 2026-08-12, and the old act was measuring a mechanism that no longer exists.**
# This act used to read `assert gas > 5.4` / `< 6.2` around a measured 5.800, because
# `vector::gas::refill_tank` put 10/s back after a 0.5 s pause. **That is gone** — the user
# closed `docs/QUESTIONS.md` Q-033 with „gas refillt nur im main gebäude", the two keys
# `gas_regen_per_s` and `gas_regen_delay_s` were deleted out of `game.ron`, and `game.ron`
# now carries an explicit ⚠️⚠️ block saying they must not come back. Against a tank that only
# falls, `> 5.4` is not a hard bracket, it is an assertion that the deleted feature is still
# running: **measured 0.300, exit 1**.
#
# So the act keeps its second claim, drops the one the game no longer makes, and turns into
# the regression guard for Q-033 itself:
#
#   - `key Ctrl` with no anchored hook does NOT want gas (`gas_budget`: `wants_reel_in =
#     pressed(REEL_IN) && hook.anchored_count() > 0`). A reel that DID cost gas cannot be
#     caught here any more — an empty tank cannot be emptied twice — so that claim now lives
#     where it can still go red: `tests/vector_gas.rs::
#     f018_reeling_in_without_an_anchored_hook_costs_nothing`.
#   - **Nothing puts gas back.** Sixty idle ticks with a key held and 180 more with nothing
#     held at all, and the number does not move off the floor. Re-introduce a 10/s regen and
#     the last assert reads ~35 instead of 0.300 and this file exits 1 — which is exactly the
#     job the old ACT 4 used to do for the opposite claim.
#
# The bracket is one tick of boost wide (0.35), for the reason set out at the top of the file:
# `f32` key countdowns do not land on a whole tick, and the dry tank reads 0.300, not 0.000.

key Ctrl 1.0             # reel-in without an anchored hook pulls on nothing
wait 1.0
mark f018-reel-without-a-hook
assert gas < 0.35        # ⭐ measured 0.300 — a held key put nothing back
assert gas >= 0          # and it did not go negative either

wait 3                   # three idle seconds: the old regen would have paid 30 gas over these
mark f018-still-dry
assert gas < 0.35        # ⭐ Q-033: gas comes back at a station and NOWHERE else
