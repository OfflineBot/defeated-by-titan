# p1-overlay — the proof that UI lands in an `--offscreen` image at all (P1 + P2).
#
#   cargo run -q -- --offscreen \
#       --script scripts/p1-overlay.txt --ticks 140 --screenshot docs/images/p1-overlay.png
#
# and, as a SEPARATE run, the one that returns a usable exit code:
#
#   cargo run -q -- --headless --script scripts/p1-overlay.txt --ticks 800
#
# ⚠️ **A `--screenshot` run is not a verdict.** `debug::screenshot::exit_when_written` owns the
# ending and writes `AppExit::Success` the moment the PNG is on disk, without ever reading
# `run.failures` — so the command above exits 0 even when the asserts in this file are RED, and
# the assert summary never prints (`docs/FINDINGS.md` FIND-073). Only the `--headless` run
# reports "N asserts held" and returns an exit code worth reading. Its tick count is
# deliberately generous (measured end: 431 ticks): overshooting the script's own end is free,
# undershooting truncates the run and hides the summary (FIND-032).
#
# This is not a feature script. It is the evidence route itself: `--offscreen` renders into
# an `Image`, and `DefaultUiCamera` answers `None` for an image target unless the camera
# carries `IsDefaultUiCamera` (bevy_ui-0.19.0/src/ui_node.rs:2991-3003). Without that
# component the run exits 0, writes a perfectly good PNG of the city — and every pixel of
# HUD is missing from it. **An empty image that looks like evidence** is the trap this file
# exists to catch (docs/PLAN-GAME.md §11, risk 3).
#
# Its twin `scripts/p1-no-overlay.txt` is the same run without the F3 line. The two PNGs
# must differ, and they must differ ONLY in the top-left corner — that difference is what
# proves the overlay is drawn, rather than the file merely having been written.
#
# ⚠️ The 140 belong to THIS file: wait 1.5 = 90 ticks at 60 Hz, then 18 + 18. Whoever
# changes a wait changes the image.

wait 1.5                # world, camera, meshes and the render pipelines come up

# The same viewpoint as scripts/f003-city.txt: 70 m up, 130 m south, 26 degrees down. A
# populated frame, so that "the overlay is on top of something" is a real statement.
look 0 -26
warp 0 70 130
wait 0.3                # the warp takes effect one tick after it is written

key F3 0.05             # switch the overlay on — a real key, through ButtonInput
wait 0.3                # one frame is enough; the extra ticks make the tick number settle

# ⚠️ **DERIVED, NOT MEASURED — re-evaluate when `gravity_m_s2` moves.** The warp lands at
# y = 70 and the two `wait 0.3` above give it a FIXED fall window of t = 0.634 s (38 ticks,
# the warp costs one). Nothing else touches the player, so the height here is free fall:
#
#     h = 70 - 0.5 * |gravity_m_s2| * t^2          t = 0.634 s
#     |g| = 32:  70 - 6.430 = 63.57   <- today, and it measures 63.575
#     |g| = 20:  70 - 4.019 = 65.98   <- the number this line used to carry, reproduced
#
# The second line is the control: the formula gives back the OLD value at the OLD gravity, so
# this is a derivation and not a re-fit to whatever the run printed.
# The bracket is +-2 simulation steps of free fall, 2*|g|*t*dt = 2*32*0.634/60 = 0.68 m —
# TIGHTER than the +-1 m it replaces, because a derived centre can afford a smaller window.
assert height > 62.9     # the warp really did take effect and he is not still at y = 70
assert height < 64.3     # and he has fallen exactly the one window, not further
# ⚠️ This line was `assert kills == 0` and it could not be measured: `Metric::Kills` reads the
# per-`PlayerId` tally off the **mission entity** (`src/debug/mod.rs::measure`), and this run
# launches without `--hub` and without a mission, so there is no tally to read. The driver
# counts an unmeasurable check as FAILED — correctly — and reported `measured nothing (no
# player found)`, which named the wrong half of the `?` chain. `phase` is the metric that is
# always measurable: `measure` documents "no mission" as the honest answer Briefing = 0.
assert phase == 0        # the new vocabulary, exercised in a real run: no mission is running
mark p1-overlay
wait 5                  # keep the run alive: if it ends, the process ends before the image
