# F-050 — the states of a husk at 25 m, and the frame in the middle of his wind-up.
#
# cargo run -- --offscreen --script scripts/f050-states.txt --ticks 433 \
#              --screenshot docs/images/f050-states.png
#
# Measured in tests/titan.rs::f050_the_husk_winds_up_for_as_long_as_the_file_says:
#   Idle 1 · Pursue 410 · Windup 36 · Strike 12 · Recover 24 · Pursue 18 ticks.
#
# `--ticks 433`, and the number is READ OFF THE IMAGE rather than derived: the overlay in
# docs/images/f050-states.png says `t=433` and `husk#1 Windup 21/36` in the same three lines.
# The header used to say 435 out of an arithmetic that started `Windup` at tick 414; the real
# entry tick is 412, and 435 photographed `23/36`. The overlay now prints the fraction, so this
# is a number that can be checked against the picture instead of recomputed — which is exactly
# what the fraction was added for.
#
# Two runs of this script give a bit-identical PNG (sha256
# c4d4681cfbd014df40229d9474389dc65bd2678158a487c664e389484e19869e on debian): a wind-up is a
# slow moment and the pose is a pure function of `(state, ticks_in_state)`.
#
# He spawns at +Z so that his spawn facing (Bevy's forward, −Z) already points at the player,
# and the whole approach is a walk instead of a 180-degree turn at 50 deg/s. The camera turns
# round to him instead.
#
# ## Why the player steps back the moment the wind-up starts
#
# `titan.ron: husk.attack_range_m` is 6.0 m, so a wind-up happens **six metres from a ten
# metre body**: at the 60-degree vertical field of view out of game.ron the image is then a
# dark underside and nothing else — measured, that was the first attempt at this picture.
#
# Once `Windup` is entered, the state runs on its tick accumulator alone; distance decides
# `Pursue -> Windup` and nothing after it. **A committed attack does not abort** — that is
# what makes a telegraph an opportunity rather than a warning, and it is why stepping back at
# tick 420 photographs the same wind-up from 24 m instead of cancelling it.
warp 0 0.05 0
look 180 0
spawn titan husk 0 0 25
wait 6.95
warp 24 0.05 6
look 90 10
# The F3 overlay, so that the KIND, the state WORD, the TICK FRACTION and the POSE stand in
# the same frame and can be checked against each other. It reads `husk#1 Windup 21/36`: the
# kind off `shared::TitanKindName`, the pair off `shared::StateClock`, both written by
# `titan::brain::advance` one system before the pose is built from the same number. Nothing
# here needed an edge from `debug` into `titan` — the two components live in shared/, which is
# why `tests/domains.rs` still passes with the allow list unchanged.
key F3 0.05
mark windup
wait 1.0
assert titans == 1
