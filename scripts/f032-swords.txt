# F-032 — **what a swing does today, at five different targets.**
#
# This file is a MEASUREMENT before it is a regression test. The user says *"attack fehlt aber
# noch (mit schwertern..)"*, and `docs/NEXT.md` §2B calls the diagnosis a hypothesis, not a
# claim: it may be that the swing never fires, that it fires and books nothing, or that it
# books something invisible. Those are three different bugs. So this run swings the same blade,
# out of the same fall, at the same husk geometry, at five heights — and the log says which.
#
# PINS: the pass speed at the target (21.0 m/s) and each act's BLADE HEIGHT as a fraction of
#       the husk (0.890 / 0.685 / 0.600 / 0.350 of `height_m`). Warp heights and x offsets
#       follow from those. Re-derived 2026-08-29 for the doubled class table and for the neck
#       in `titan::rig::body_segments_m` — the clearance is `widest_between_m` over the
#       player's 1.8 m, which is 1.706 m at the nape and 2.850 m at chest and arm height.
#
#   cargo run -q -- --headless --script scripts/f032-swords.txt --ticks 1200
#   # the exit code needs its OWN run — a pipeline's $? is the LAST command's:
#   ./target/debug/defeated_by_titan --headless --script scripts/f032-swords.txt --ticks 1200 >/dev/null 2>&1; echo $?
#
# ## The five acts, and why each one stands where it does
#
# Every act is the SAME pass: the player falls **6.891 m** onto the target at **21 m/s** in
# **0.656 s**, stands 1.80 m off the husk's axis, looks at yaw 0 so the RIGHT blade lies on +X
# (`src/blades/cut.rs: blade_segment`), and slashes **0.506 s** into the fall so that the blade's
# active window (`gear.ron`: 0.08..0.22 s of a 0.35 s swing) brackets the crossing.
# **Only the HEIGHT changes** — and with it which part of the husk the blade passes through.
#
# 🔴 **Those three numbers are DERIVED from `game.ron: gravity_m_s2` and must never be re-aimed
# by hand.** The constant is the pass SPEED, because that is what the game reads: `damage =
# blades.damage_per_m_s x closing_m_s x zone x combo`, and `feel.strong_hit_m_s` 18.0 is what
# splits a CUT from a GRAZE. 21 m/s clears that by 17 %. Everything else follows:
#
#     g      = -game.ron: gravity_m_s2 = 32.0
#     drop   = v² / (2 g) = 441 / 64 = 6.891 m        (was 11.20 m at g = 20)
#     t_fall = v / g      = 0.656 s                   (was 1.058 s)
#     wait   = t_fall - (active_from_s + active_to_s) / 2 = 0.656 - 0.15 = 0.506
#
# **The control that says this is a derivation and not a fresh guess: put g = 20 back in and it
# prints `wait 0.900` and `drop 11.03 m`** — the calibration this file carried until 2026-08-29.
# The full write-up is in the header of `scripts/f030-cortex.txt`.
#
# A husk is the `medium` class: height 10.00 m, width `width_fraction × h` = 2.50 m
# (`scale.ron`), so his ONE body collider is a capsule of radius 1.25 m about his axis
# (`src/titan/rig.rs:358`). Everything below is derived from those two numbers:
#
# ## 🔴 WHERE THE FIVE ACTS STAND, and it changed on 2026-08-29
#
# They stood at `z` 0, 150, 300, **450 and 600** — and Ashgate is 700 x 700 m, so the last two
# were 100 and 250 m OUTSIDE the map. `F-012`'s recovery teleported the player home on the next
# tick, twice per run, and because no act here asserts a position the file went on measuring a
# player who had been moved: acts D and E were flown from `(-1.80, 2.00, 300)`, the previous
# act's ground, and still exited with the same numbers.
#
# The five lanes now run along the **boulevard** `(0, -0.1, -83.75) x (700, 0.3, 27.5)` — a
# cleared paved strip across the full width of the district, no house on it and no terrace over
# it. Probed 2026-08-29 at x = -300, -200, -100, 0, 100, 200, 300: the resting height is
# **0.050 m at every one of them**, which the old z-lanes were not (z 0 read 0.050, z 150/300
# read 1.500). So the five acts now stand on identical ground for the first time.
#
# ⚠️ **Not one number in the pass changed.** The titan still spawns at `y = 0`, the player is
# still warped to an absolute height and still falls onto the nape (`11.20 m` then, the derived
# `6.891 m` since the gravity change of 2026-08-29 — same speed, same crossing), still stands
# `1.80 m` off the axis on -X and `0.55 m` behind it on +Z, still looks yaw 0. Only the lane
# moved, and it moved as a rigid translation: `x` carries the lane, `z` carries the same
# `+0.55` set-back it always had.
#
# 🔴 **THE HUSK IS 20 m SINCE 2026-08-29** (`scale.ron`'s classes doubled on the user's word),
# so every metre below is twice what it was and the x offsets are no longer 1.80 for all four:
# at the nape the player clears a NECK (1.550 + 0.20 = 1.750), at chest and arm height he clears
# the TORSO (2.350 + 0.20 = 2.550). **`blade y` as a fraction of the body is the column that
# carries the meaning and it did not move.**
#
# | act | the part the blade passes through | its metres | blade y | x offset | player y at warp |
# |---|---|---|---|---|---|
# | A | the **nape** — the cortex sphere, r 1.10, 1.10 m behind the neck | y 17.80 | 17.80 | 1.750 | 23.091 |
# | B | the **torso** box, `leg_m` 9.60 .. `cortex` 17.80, centre 13.70 | y 9.60..17.80 | 13.70 | 2.550 | 18.991 |
# | C | the **left arm** box, shoulder 16.40 down `arm_m` 8.80 to 7.60 | y 7.60..16.40 | 12.00 | 2.550 | 17.291 |
# | D | the **left leg** box, ground to `leg_fraction × h` | y 0..9.60 | 7.00 | 2.550 | 12.291 |
# | E | **nothing at all** — 150 m from the nearest titan | — | 17.80 | 1.750 | 23.091 |
#
# `player y at warp` is always `blade y − eye_height_m 1.60 + drop`, and `drop` is the derived
# 6.891 m above. **`blade y` is the column that carries the meaning and it did not move** — the
# four heights on the husk are the same four heights they were; only the run-up to them is
# shorter. Recompute the last column from `drop` and never from the previous run's numbers.
# The five titans stand 150 m apart in z so that no husk of a finished act is inside the
# `aggro_radius_m: 45` of the next one — a husk walks 3 m/s and the whole run is 14 s.
#
# ## What the asserts claim, and what they deliberately do NOT claim
#
# They claim only the **outcome a player can see**: the nape kills, the other three do not.
# Which `HitZone` each act reports, at what closing speed, and whether a `TitanHit` is written
# at all is read off `src/blades/cut.rs`'s own `info!` line —
#
#   tick 154: cut titan 1 Cortex at 20.67 m/s (player 1)
#
# — because no `assert` metric in `src/debug/script.rs` can see a zone, a titan's health or a
# titan's freeze. That is the table this run exists to produce, and **this is what it produced**
# on 2026-08-19, first run, 11 of 11 asserts held:
#
# | act | target | what the log said | what happened to the titan |
# |---|---|---|---|
# | A | nape | `tick 154: cut titan 1 Torso at 20.67 m/s` **then** `tick 157: … Cortex at 21.00 m/s` | dead |
# | B | torso | `tick 327: cut titan 2 Torso at 20.67 m/s` | **nothing** |
# | C | arm | `tick 500: cut titan 3 Torso at 20.67 m/s` | **nothing** |
# | D | leg | `tick 673: cut titan 4 Torso at 20.67 m/s` | **nothing** |
# | E | air | *(no line)* | — |
#
# **And this is the same table after the 2026-08-29 gravity re-derivation** — same five verdicts,
# 24 ticks earlier, and every act now books the limb it flies through instead of reporting
# `Torso` for all four (the limb boxes carry colliders now; that is drift since 2026-08-19 and
# not this round's):
#
# | act | target | what the log says today | what happened to the titan |
# |---|---|---|---|
# | A | nape | `tick 130: cut titan 1 Torso at 20.27 m/s` **then** `tick 133: … Cortex at 20.80 m/s` | dead |
# | B | torso | `tick 279: … Torso at 20.27` then `tick 282: … ArmLeft at 20.80` | **nothing** |
# | C | arm | `tick 428: … ArmLeft at 20.27` then `tick 436: … LegLeft at 23.47` | **nothing** |
# | D | leg | `tick 577: … LegLeft at 20.27 m/s` | **nothing** |
# | E | air | *(no line)* | — |
#
# ⚠️ **The three-tick gap between the graze and the nape in act A survived the change** (154→157
# then, 130→133 now), and it is not decoration: it is the whole premise of
# `tests/combat.rs::f032_a_cortex_hit_assigns_the_kill_frame_over_any_stagger`.
#
# **So it is the third of the three bugs `docs/NEXT.md` §2B listed: the swing fires, the cast
# lands, a `TitanHit` IS written — and nothing in the repository reads it.** Not "the swing never
# fires" and not "it fires and books nothing". Two further facts fall out of the same table:
#
#  * **arm, leg and torso are one zone.** A titan has exactly ONE body collider, the root capsule
#    (`src/titan/rig.rs:358`); the limb boxes carry meshes and no colliders at all, and every limb
#    sits inside a capsule of radius `width_m / 2`. `HitZone::ArmLeft`/`LegLeft`/`Head` have never
#    been produced by anything in this game.
#  * **the graze precedes the nape by three ticks** (154 → 157 then, 130 → 133 today) and not by
#    zero, which is why
#    `combat::hitstop` has to ASSIGN the kill frame rather than take the longer of the two
#    (`tests/combat.rs::f032_a_cortex_hit_assigns_the_kill_frame_over_any_stagger`).
#
# Since 2026-08-19 acts B, C and D additionally **stagger** the husk for
# `titan.ron: husk.stagger_s` = 0.22 s = 13 ticks (`F-032`). That is not assertable from a script
# — no metric reaches a titan's `HitStop` — and it is carried by
# `tests/titan.rs::f032_a_grazed_titan_holds_still_for_his_whole_stagger`, which measures the
# ground he does NOT cover.
#
# ⚠️ **The control run this file owes** (rule 5 / `FIND-103`): act A must go RED when the blade
# is taken away. `settings` cannot dull a blade from a script, so the control is done in Rust —
# `tests/combat.rs` casts the same geometry with `reach_m` at 0 and gets no hit. A run that
# would pass with no blade in it is measuring gravity, not swordplay.

# 1.5 s of lead-in: the world's blocks are still coming up in the first second.
wait 1.5

# ---- ACT A — the nape. The one hit the game already has. --------------------------------
spawn titan husk -300 0 -83.75
warp -301.750 23.091 -82.65
look 0 0
wait 0.506
slash right 0.40
mark A-cortex
# The crossing is ~0.16 s after the button. 0.60 s covers the whole active window with room.
wait 0.60
assert titans == 1
# `death_s: 1.0` — the body dissolves for a second before it is gone.
wait 1.30
assert titans == 0

# ---- ACT B — the torso, dead centre of the body box. -------------------------------------
spawn titan husk -150 0 -83.75
warp -152.550 18.991 -82.65
look 0 0
wait 0.506
slash right 0.40
mark B-torso
wait 0.60
assert titans == 1
wait 1.30
# **The claim of this act:** a blade through the chest does not kill. That is the design
# ("only the Cortex kills") and it must survive F-032.
assert titans == 1

# ---- ACT C — the left arm. -----------------------------------------------------------------
spawn titan husk 0 0 -83.75
warp -2.550 17.291 -82.65
look 0 0
wait 0.506
slash right 0.40
mark C-arm
wait 0.60
assert titans == 2
wait 1.30
assert titans == 2

# ---- ACT D — the left leg. -----------------------------------------------------------------
spawn titan husk 150 0 -83.75
warp 147.450 12.291 -82.65
look 0 0
wait 0.506
slash right 0.40
mark D-leg
wait 0.60
assert titans == 3
wait 1.30
assert titans == 3

# ---- ACT E — the same swing at nothing. ----------------------------------------------------
# The null case. Without it "the blade reports a hit" is not a measurement of the blade — it
# could be a measurement of the swing firing at all.
warp 298.250 23.091 -82.65
look 0 0
wait 0.506
slash right 0.40
mark E-air
wait 0.60
assert titans == 3
wait 1.30
assert titans == 3
# `assert kills` is deliberately NOT here: the tally is `mission`'s and this run carries no
# `--mission`, so the line reported "measured nothing" rather than a number (measured, first run
# 2026-08-19). `titans` already carries the whole claim — one husk gone, three standing.
#
# 🔴 **THIS LINE WAS CHANGED TO `== 0` ON 2026-08-29 AND CHANGED BACK THE SAME DAY.**
#
# The re-aim round wrote `assert health == 0` under a derivation — *3 surviving husks x
# `titan.ron: husk.damage` 34 = 102 >= `game.ron: player.health` 100* — and an adversary killed
# it with the control the derivation was missing: **that arithmetic contains no gravity, so it
# predicts 0 at BOTH tunings.** Run this same file against `gravity_m_s2: -20` / `boost_m_s2: 34`
# and it reads **11 asserts held, including `health > 0`**. At `-32` the player dies.
#
# So the player dying here is a **behaviour change the heavier world caused**, and writing it
# into the assert is the one thing `CLAUDE.md` forbids: it converts a regression into a
# calibration and the corpus stops being able to report it. Filed as **`docs/BUGS.md` B-020**
# and left RED until somebody decides whether a player SHOULD survive three husks at -32.
# ⚠️ Do not "fix" this by raising `player.health` either — that is the same move one file over.
assert health > 0
end
